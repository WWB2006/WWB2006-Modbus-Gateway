## 阶段 4–11 覆盖的关键用例

### 串口 RTU（阶段 4，35 项）

| 分组 | 关键用例 |
| --- | --- |
| RTU 组帧 | 单元号 + PDU + CRC，CRC 低字节在前 |
| RTU 解帧 | 请求帧与响应帧方向不同，用不同函数解 |
| RTU 会话 | 通过串口链路读保持寄存器（假串口链路驱动） |
| 分帧 | 半包拼齐、坏 CRC 丢弃 |
| 异常响应 | 不重传，直接给出中文提示 |
| 总线过滤 | 单元号不匹配的响应被丢弃 |
| 帧间静默 | 9600 8E1 → 5ms（3.5 字符时间，11 bit/字符） |
| 帧长对照 | TCP 帧比 RTU 帧长 4 字节（MBAP 7 − 单元号 1 − CRC 2） |

### 配置解析（阶段 10，72 项）

| 分组 | 关键用例 |
| --- | --- |
| JSON 基础 | 对象 / 数组 / 标量 / 嵌套 |
| JSON 错误 | 语法错误带**行列号**定位 |
| 网关配置 | 多设备与点位、缺省值 |
| 拒绝非法 | 设备名重复、`unitId > 247`、功能码非 {3,4,6}、`count > 125`、`parity` 非 {N,E,O} |
| 真实文件 | 仓库内 `config/gateway.json` 可解析且含 3 台设备 |

### 存储与指标（阶段 6+7，80 项）

| 分组 | 关键用例 |
| --- | --- |
| 双实现同契约 | 内存实现与 SQLite 实现跑同一批断言（排序、时间范围闭区间、`limit`） |
| 主键去重 | 同一 `(device, ts_ms, address)` 重写不增加条数，值被替换 |
| 批量语义 | `batchSize=3` 时 7 条样本全部落盘、缓冲清空；未达阈值时缓冲留住数据 |
| close 兜底 | 写入后不 flush 直接 `close()`，重开库仍能读到 |
| CSV | 含逗号/引号/中文标点的 `note` 正确转义并回读 |
| 分位数 | 最近秩法；超时样本不计入延迟分位 |
| 滑动窗口 | 容量 5 的窗口记 10 条后只保留最近 5 条（`windowSize == 5`）；累计计数仍为 10 |

### 异常注入（阶段 8，79 项）

| 分组 | 关键用例 |
| --- | --- |
| 六类决策 | `NoResponse` / `CorruptCrc` / `ExceptionCode` / `TruncatedFrame` / `BadProtocolId` / `DelayedResponse` 各自命中条件 |
| 字节效果 | 篡改后的字节确实是坏 CRC / 截断长度 / 非法协议标识 |
| 计数与上限 | `maxInjections` 到达后不再注入 |
| 时序 | `startAfter` 之前的请求不受影响；`interval` 控制注入频率 |
| 过滤 | `functionCode` 过滤只影响指定功能码 |
| 优先级 | 多条规则同时命中时的先后 |
| 配置解析 | 规则从 JSON 读入并校验 |

### 退避重连（阶段 9，40 项）

| 分组 | 关键用例 |
| --- | --- |
| 掉线调度 | 链路转 Error 时安排重连，并中止在途事务 |
| 恢复 | 链路回来后重连成功、恢复轮询、上报 `Recovered` |
| 退避序列 | 间隔 **100 → 200 → 400 → 800ms**，之后封顶 |
| 主动停止 | `stop()` 之后不再重连（主动断开不能被当成掉线） |
| 策略关闭 | `reconnect.enabled = false` 时不重连 |
| 管理器转发 | 管理器把会话的链路事件正确转发给上层 |

### 原生 TCP 链路与注册表（阶段 11，41 项）

| 分组 | 关键用例 |
| --- | --- |
| 注册表三态 | 未注册 → 返回空 + 可读原因；注册 → 可造出实例；注销 → 回到不可用 |
| 错误路径 | 连不存在的端口失败且状态转 Error、**10 秒内返回**（不卡到系统默认超时）、未连接时 `send`/`pollOnce` 安全失败、重复 `close` 幂等 |
| 真实收发 | 起从站模拟器走 **loopback socket**：发真实 Modbus TCP 请求、收响应、解帧、断言 HR[0..3] = 100/250/380/7；再发写请求并断言从站侧真的被写入 |
| 驱动转发 | `DeviceManager::pump()` 把驱动请求转达到链路 |

## 本批修正的缺陷

| 缺陷 | 症状 | 根因 | 修正 |
| --- | --- | --- | --- |
| 掉线重连静默失效 | 界面显示"链路断开"但永不重连，**无任何报错** | `DeviceSession::attach` 与 `DeviceManager::addDevice` 都注册 `transport->onState`，回调槽单订阅者 → 后者覆盖前者 | 确立「链路状态唯一所有者 = 会话」；管理器改读 `session->linkState()`；`TransportInterface` 注释写明契约 |
| CMake 路径不编 sqlite | CMake 构建链接失败（`undefined reference to sqlite3_*`） | `third_party/sqlite/sqlite3.c` 从未加入任何 target，项目也没启用 C 语言 | 顶层启用 `LANGUAGES CXX C`；`sqlite3.c` 编入 `gateway_core`；编译选项与可移植脚本对齐 |
| CMake 漏加 metrics 目录 | `undefined reference to metrics::Collector::*` | 源文件收集是逐目录列举，新增 `src/metrics/` 时漏改 | 改为整体 glob `src/*/*.cpp` 再剔除 Qt 专属文件 |
| ctest 下 config_tests 失败 | 脚本里全绿、ctest 里红 | 用例靠当前工作目录猜仓库位置（`../config/gateway.json`），而 ctest 的工作目录是 `build/<cfg>/tests/portable/` | 仓库根目录由 `argv[1]` 显式传入（ctest 传 `${CMAKE_SOURCE_DIR}`，脚本传 `$root`） |
| PS1 脚本语法报错 | `表达式或语句中包含意外的标记 ')'` | 文件是 UTF-8 无 BOM，Windows PowerShell 5.1 按 ANSI 解码中文注释导致错乱 | 写入 UTF-8 BOM |
| 导出 CSV 恒为空 | `--export-csv` 生成只有表头的文件 | 时间范围上界传了 uint64 最大值，绑成 `sqlite3_int64` 后变成 −1，`ts_ms <= -1` 恒假 | 上界改用 int64 最大值 `0x7FFFFFFFFFFFFFFF` |
| 断言写错（非代码错） | `storage_tests` 两处失败 | ① 批量语义断言读了 `ArchiveResult::pending` 而该字段语义不同；② P95 均值手算漏了 1000ms 样本（19ms 应为 28ms） | 补 `archived` 字段并修正断言；均值断言附上算术过程 |
| 根目录游离测试产物 | 仓库根出现 `test_slave_config*.json` | 早期版本的测试从仓库根运行 | 测试统一在构建目录内运行；删除已产生的游离文件 |

## 已知限制

1. **界面层（阶段 5）与串口链路（阶段 4）本机无法编译验证**：
   开发机只有 MinGW g++ 8.1.0（过旧，无法编 Qt 6）且未安装 Qt。
   这两部分靠「可移植测试 + CMake 条件编译 + Linux CI」保证正确性。
   串口链路的**协议逻辑**（RTU 组帧、解帧方向、帧间静默）已用假串口链路覆盖 35 项断言，
   但 QSerialPort 的接线（端口名、波特率设置）需要在有 Qt 的机器上实测。
2. **无 Qt 构建的 daemon 不支持 `rtu` 设备**（串口只有 Qt 实现）。
   启动时会明确打印 `[不可用] ... 不支持 rtu 链路`，不会静默跳过。
3. **`gateway_daemon` 在 Qt 构建下也用原生链路**，不用 `TcpTransport`。
   这是刻意的取舍（一致性优先于复用），代价见 ADR 0005。
4. **SQLite 版本升级需手工替换** `third_party/sqlite/` 下的文件。
   这是刻意的：升级应当是一次有意识的提交，而不是某次系统更新的副作用。
