# ADR 0001：分层结构与依赖方向

- 状态：接受
- 日期：2026-10-08

## 背景

工业网关同时要处理协议、两条链路（TCP 与串口）、设备轮询、存储、模拟器与界面。
如果界面类直接调用网络代码、网络代码里又内嵌协议拼包，会同时带来三类问题：
无法脱离硬件测试、无法复用 PDU 逻辑、重构界面时牵动通信代码。

## 决策

按 `protocol / transport / device / storage / sim / ui / util` 分层，依赖方向单向：

```
ui -> device -> transport -> protocol
                   |            ^
                   v            |
                storage       sim
```

其中 **protocol 层不允许依赖 Qt**，只使用标准库：编解码函数接收 `const uint8_t*` 与长度，
返回结构体，不抛异常、不做动态分配以外的事情，缓冲区由调用方提供。

## 理由

1. 协议层能脱离网络做单元测试，半包、粘包、坏 CRC 可以直接构造字节数组验证；
2. 同一份 PDU 逻辑同时服务 TCP 与 RTU，两条链路只在帧头帧尾不同；
3. 协议内核可以移植到 MCU 侧，为后续「软硬联调」留出空间；
4. 界面只依赖 device 层的信号与数据模型，改界面不会碰到通信代码。

## 代价

1. 需要手动管理缓冲区生命周期，调用方要清楚数据所有权；
2. 不能使用 `QByteArray` 的便利方法，字符串与容器都用标准库；
3. 跨层传递需要写转换代码（例如标准库容器与 Qt 容器互转）。

## 备选方案

- **直接用 QModbusTcpClient / QModbusRtuSerialMaster**：上手快，但协议细节被封在库里，
  面试无法展开，且无法自定义故障注入与异常码行为。本项目仅把它作为交叉验证的参考实现。
- **把协议逻辑写进 TcpTransport**：省一层抽象，但 RTU 复用不了，测试必须起真实 socket。
