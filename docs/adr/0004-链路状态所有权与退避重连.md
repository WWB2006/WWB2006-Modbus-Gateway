# ADR 0004：链路状态只有一个所有者（会话），重连用指数退避

- 状态：接受
- 日期：2026-10-13

## 背景

阶段 9 要解决「设备掉线后自己恢复」。掉线信号来自链路（`TransportInterface::onState`），
需要被两处知道：会话（要中止在途事务并安排重连）、管理器/界面（要记日志、更新状态显示）。

最初的写法是两边各自注册：

```cpp
// DeviceSession::attach
transport.onState([this](TransportState s) { /* 触发重连 */ });

// DeviceManager::addDevice
transport.onState([this, name](TransportState s) { /* 更新界面 */ });
```

而 `TransportInterface` 的回调槽是**单订阅者**（后注册覆盖先注册）。
于是 `addDevice` 把会话的回调覆盖掉了 —— **掉线重连静默失效**：
界面能正确显示"链路断开"，但永远不会重连。日志一切正常，没有任何报错。

这个 bug 的特征值得记住：它不报错、不崩溃、测试如果只测"状态显示对不对"也会通过。

## 决策

**链路状态的唯一所有者是 `DeviceSession`**：

- `TransportInterface::onState` 只由 `DeviceSession::attach` 注册一次；
- `DeviceSession` 通过 `linkState()` 对外提供当前状态查询；
- `DeviceManager::state(name)` 改为读 `session->linkState()`，不再自己维护一份；
- `DeviceManager` 想转发事件，就注册**会话的** `setLinkCallback`，而不是链路的 `onState`。

同时在 `TransportInterface` 的注释里把"每个回调槽只允许一个订阅者"
从隐含约定变成显式契约，避免下一个人再踩。

重连策略：**指数退避**，`initialDelayMs=1000`、`multiplier=2`、`maxDelayMs=30000`，
且前 `failuresBeforeBackoff=2` 次失败不进入退避（用初始延迟快速重试）。

## 理由

1. **单一所有者消除了整类 bug**：状态有两个所有者时，"谁覆盖谁"取决于调用顺序，
   而调用顺序又会随重构改变。这不是"小心一点"能解决的问题，是结构问题；
2. **为什么不立刻重连**：现场设备掉电或网线被拔时，每秒重连几十次会把设备的
   TCP 连接表打满，设备恢复后反而因为资源耗尽连不上；
3. **为什么前几次不退避**：现场多数掉线是瞬时的（交换机抖动、设备重启）。
   头两次快速重试能在 1 秒内恢复，而一上来就等 30 秒会让采集出现明显空洞；
4. **为什么重连时先中止在途事务**：否则那个事务会一直"等响应"直到超时，
   上层会误以为设备还在线。中止比等待诚实。

## 代价

1. `DeviceSession` 承担了比"一个请求-响应会话"更多的职责（还管链路生命周期）。
   这是有意的：状态的所有权必须跟着"谁最需要它做决策"走，而最需要它的是重连逻辑；
2. 界面/网关想拿链路状态必须经过会话（多一层）。换来的是"状态不会有两个版本"。

## 验证

`tests/portable/recovery_tests.cpp`（40 项断言）用假链路 `ControllableTransport`
覆盖：掉线调度重连、恢复后重连成功、退避序列 100→200→400→800ms、
`stop()` 后不再重连、在途事务被中止、策略关闭时不重连、管理器正确转发链路事件。
其中"退避序列"这条断言直接钉住了上面那个静默失效的 bug —— 它一旦回归就会红。
